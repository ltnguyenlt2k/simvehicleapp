# S-R4 transport feasibility — measurement in progress

Protocol prototype: real grpc.aio server in a separate spawned process, actual
loopback socket, one provider and four subscribers. 50 distinct paths per 9.9 ms
offer slightly above 5,000 samples/s; measured rate must stay >=5,000, without
rounding or tolerances. Every subscriber must receive every offered sample.

Full measurement: 1,800 seconds. Container sr-m23-s-r4, network none (internal
loopback only), CPU limit 2, memory limit 256 MiB, non-root uid 1000. The existing
dog and vehicle services remain active, so this is measured shared-host evidence,
not a universal minimum host specification. Python 3.12.15, grpcio/grpcio-tools
1.85.0 and protobuf 7.36.2; exact image is retained in Docker inspect.

Acceptance targets fixed before the full run:

- Actual measured input rate >=5,000 samples/s; four complete subscribers.
- Broker-ingest-to-subscriber p95 <5 ms over the entire run. A 0.01 ms histogram
  upper bound computes the total percentile; a rolling window is also reported.
- Broker-process RSS growth <=8,192 KiB comparing stabilized second minute and
  final minute. This bounds growth in the measured envelope; it does not prove
  the absence of every possible long-term leak. RSS sampled approximately once/s.
- No producer/subscriber or queue-overflow errors; all data delivered.

Capped 10 s smoke: PASS, 50,500 samples, all four subscribers received 50,500;
measured 5,049.3/s, p95 0.71 ms. This is not the 30-minute gate. Production
broker validation, leases, STOP and other safety invariants are not implemented
by this prototype and cannot be accepted from this test.

Raw output: robotics/runtime/m23/s-r4-full.json after completion, retained
container logs until report closure. T03 waits for the full gate.
